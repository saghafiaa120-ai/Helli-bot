# حلی بات (Helli bot)

ربات فارسی مدیریت و امنیت گروه برای تلگرام، با معماری قابل توسعه برای پلتفرم‌های دیگر.

**وضعیت: فاز ۲ (مدیریت کاربران) + آمار پیام‌ها + پنل کاربری دکمه‌ای.**

## امکانات

**فاز ۱ — هسته**
- ثبت خودکار گروه‌ها، خروج ربات و انتقال گروه به سوپرگروه
- همگام‌سازی مدیران واقعی و بررسی دسترسی‌های خود ربات
- ثبت کاربران و وضعیت عضویت
- `/start` و `/help`

**فاز ۲ — مدیریت کاربران** (فقط مدیران؛ روی پیام کاربر Reply کنید، یا شناسه عددی / @نام‌کاربری بدهید)

| دستور | معادل فارسی | کار |
| --- | --- | --- |
| `/ban [مدت] [دلیل]` | مسدود | مسدود کردن. بدون مدت = دائمی و **با دکمه تأیید** |
| `/unban` | رفع مسدودیت | رفع مسدودی |
| `/mute [مدت] [دلیل]` | سکوت | بی‌صدا کردن (بدون مدت = دائمی) |
| `/unmute` | رفع سکوت | رفع سکوت |
| `/kick [دلیل]` | اخراج | اخراج (می‌تواند دوباره عضو شود) |
| `/warn [دلیل]` | اخطار | ثبت اخطار |
| `/unwarn` | حذف اخطار | لغو آخرین اخطار فعال |
| `/info` | اطلاعات | اطلاعات کاربر (بدون هدف: خودتان) |
| `/warnings` | اخطارها | فهرست اخطارهای کاربر |
| `/panel` | پنل | پنل کاربری دکمه‌ای (آمار، اطلاعات، تنظیمات) |

مدت‌زمان: `30s` ثانیه، `10m` دقیقه، `2h` ساعت، `1d` روز، `1w` هفته، یا فارسی مثل «۱۰ دقیقه» و «دائمی».
حداقل ۳۰ ثانیه و حداکثر ۳۶۶ روز است (تلگرام خارج از این بازه آن را «دائمی» حساب می‌کند).
دستورهای فارسی بدون اسلش نوشته می‌شوند (مثلاً Reply + «سکوت ۱۰ دقیقه»)؛ برای غیرمدیرها پاسخی نمی‌دهند.

قواعد:
- اخطارها به سقف (پیش‌فرض ۳) که برسند، کاربر **۲۴ ساعت** بی‌صدا و شمارنده صفر می‌شود. هرگز مسدودی دائمی خودکار اعمال نمی‌شود.
- روی مدیران گروه، خود ربات و خودتان نمی‌شود ban/mute/kick/warn کرد.
- مدیری که دسترسی «محدود کردن کاربران» ندارد، با ربات هم نمی‌تواند ban/mute/kick کند.
- همه اقدامات در جدول `moderation_actions` ثبت می‌شوند.
- اگر مدیری از منوی خود تلگرام کسی را آزاد یا محدود کند، سوابق ربات هم‌گام می‌شود (نیازمند مدیر بودن ربات).

**آمار پیام‌ها و گزارش شبانه**
- ربات تعداد پیام‌های هر نفر را در هر روز می‌شمارد (فقط عدد؛ متن پیام‌ها ذخیره نمی‌شود).
- هر شب ساعت **۲۳:۵۹ به وقت تهران**، ده نفر فعال‌ترین گروه را در گروه اعلام می‌کند.
- `/stats` (آمار): آمار امروز تا این لحظه. `/dailystats on|off` (آمار شبانه روشن/خاموش): روشن/خاموش کردن گزارش شبانه. هر دو مخصوص مدیران‌اند.
- شمارش‌ها ۹۰ روز نگه داشته می‌شوند. اگر ربات ساعت ۲۳:۵۹ خاموش باشد، گزارش آن شب ارسال نمی‌شود.
- پیام‌های خدماتی (ورود، خروج، سنجاق و ...) و پیام‌های ربات‌ها شمرده نمی‌شوند.

## پنل کاربری (`/panel` یا «پنل»)

پنل با دکمه‌های شیشه‌ای کار می‌کند و دو حالت دارد:

**داخل گروه** (فقط مدیران): خلاصه گروه (تعداد اعضا، پیام‌های امروز، سقف اخطار) و دکمه‌های:

| دکمه | کار |
| --- | --- |
| 📊 آمار امروز | جدول ده نفر فعال‌ترین امروز |
| 👤 اطلاعات من | کارت اطلاعات خودتان (نقش، اخطار، محدودیت، مجموع پیام) |
| ⚙️ تنظیمات | تغییر تنظیمات همان گروه (پایین‌تر) |
| 📖 راهنما | همان متن `/help` |
| 🔄 به‌روزرسانی | تازه‌سازی آمار پنل |
| ❌ بستن | حذف پیام پنل |

**در گفتگوی خصوصی**: فهرست گروه‌هایی که کاربر در آن‌ها مدیر است (۶ گروه در هر صفحه) با آمار امروز هر گروه؛
با انتخاب هر گروه، آمار و تنظیمات همان گروه باز می‌شود. مالک ربات (از `OWNER_IDS`) همه گروه‌های فعال را می‌بیند.

دسترسی‌ها در هر بار زدن دکمه دوباره بررسی می‌شوند؛ دکمه‌های قدیمی برای کسی که دیگر مدیر نیست کار نمی‌کنند.

## تنظیمات هر گروه (از پنل)

تنظیمات از مسیر «پنل ← تنظیمات» تغییر می‌کند (هر گروه مستقل است):

| تنظیم | مقادیر | ذخیره‌سازی |
| --- | --- | --- |
| گزارش شبانه | روشن / خاموش | `group_settings.settings.daily_report` |
| سقف اخطار | ۳ ← ۵ ← ۱۰ ← بدون سقف | `group_settings.settings.warn_limit` (۰ = بدون سقف) |
| سکوت خودکار | ۱ ساعت ← ۶ ساعت ← ۲۴ ساعت ← ۷ روز | `group_settings.settings.warn_mute_seconds` |
| تأیید مسدودی دائمی | روشن / خاموش | ستون `group_settings.confirm_sensitive_actions` |

روشن/خاموش کردن گزارش شبانه با `/dailystats on|off` هم ممکن است. مقادیر را می‌توان دستی هم در دیتابیس اصلاح کرد؛
مقدارهای نامعتبر هنگام خواندن با پیش‌فرض (۳ اخطار، ۲۴ ساعت) جایگزین می‌شوند.

## اجرا با XAMPP (ویندوز)

نیازمند **Python 3.12+** و **XAMPP** با MySQL/MariaDB.

**۱) دیتابیس را بسازید**
- XAMPP Control Panel → `Apache` و `MySQL` را Start کنید.
- `http://localhost/phpmyadmin` → تب Databases → نام `helli`، collation `utf8mb4_unicode_ci` → Create.

**۲) وابستگی‌ها**

```bash
python -m venv .venv
.venv\Scripts\activate            # در Git Bash: source .venv/Scripts/activate
pip install -r requirements.txt
```

**۳) تنظیمات**

فایل `.env` در ریشه پروژه (نه `.env.txt`). حداقل دو مقدار لازم است:

```dotenv
BOT_TOKEN=123456:ABC...
DATABASE_URL=mysql+asyncmy://root:@127.0.0.1:3306/helli?charset=utf8mb4
```

- کاربر پیش‌فرض XAMPP `root` با رمز خالی است. اگر رمز گذاشته‌اید: `mysql+asyncmy://root:رمز@127.0.0.1:3306/helli?charset=utf8mb4`
- اگر رمز کاراکتر خاص دارد، URL-encode کنید (`@` → `%40`، `#` → `%23`).
- `OWNER_IDS` اختیاری است؛ شناسه عددی خودتان را بگذارید تا در همه گروه‌ها دسترسی کامل داشته باشید.

**۴) ساخت جدول‌ها**

```bash
alembic upgrade head
```

هر بار که نسخه جدیدی از پروژه گرفتید، این دستور را دوباره اجرا کنید (Migrationهای جدید را اعمال می‌کند).

**۵) اجرا**

```bash
python run.py
```

پنجره را باز نگه دارید؛ بستن آن ربات را خاموش می‌کند. لاگ‌ها در همان پنجره چاپ می‌شوند.

> اگر خطای `Access denied` یا `Can't connect to MySQL server` گرفتید، یعنی MySQL در XAMPP روشن نیست
> یا رمز `root` در `DATABASE_URL` با رمزی که در phpMyAdmin تنظیم کرده‌اید یکی نیست.

## تنظیم ربات

1. در BotFather دستور `/setprivacy` را روی **Disable** بگذارید، یا ربات را مدیر گروه کنید.
2. ربات را به گروه اضافه کنید و **مدیر** کنید با دسترسی‌های «حذف پیام‌ها» و «محدود کردن کاربران».
3. برای دستورات مدیریتی، مدیرها نباید در حالت «ناشناس» (Anonymous) پیام بدهند؛ ربات نمی‌تواند هویتشان را تشخیص دهد.
4. رویدادهای ورود/خروج اعضا و تغییر مدیران فقط وقتی ربات مدیر است دریافت می‌شوند.

## راهنما (`/help`)

راهنما به‌جای یک متن بلند، **بخش‌بندی‌شده** است: صفحه اصلی (شروع سریع و پرتکرارترین دستورها)
و چهار بخش که با دکمه باز می‌شوند:

| بخش | محتوا |
| --- | --- |
| 👮 مدیریت کاربران | ban / mute / kick / warn / info و قواعد |
| 📊 آمار و گزارش | stats / dailystats و نکته‌های شمارش |
| 🎛 پنل کاربری | دکمه‌ها و تنظیمات قابل تغییر |
| ⏱ مدت‌زمان | واحدها، معادل فارسی و محدوده مجاز |

دستورها داخل `<code>` نمایش داده می‌شوند (مونواسپیس) و توضیح‌های مهم در `blockquote` تا از متن جدا باشند.
دکمه «📖 راهنما» در پنل هم همین راهنما را باز می‌کند.

## تست

```bash
pip install -r requirements-dev.txt
pytest        # ۱۲۲ تست
ruff check .  # تنظیمات در ruff.toml
```

| فایل | پوشش |
| --- | --- |
| `test_config.py` | خواندن `.env`، اعتبارسنجی توکن و تبدیل URL |
| `test_permissions.py` | نقش‌ها و مجوزهای داخلی |
| `test_dto_texts.py` | متن‌های فارسی، قالب‌بندی اعداد و واقعی‌بودن دستورهای راهنما |
| `test_telegram_mapping.py` | تبدیل نوع‌های تلگرام به ساختار داخلی |
| `test_commands.py` | تجزیه دستور/مدت (فارسی و لاتین) و تاریخ شمسی |
| `test_services.py` | گروه، کاربر، مدیران و عضویت روی SQLite |
| `test_moderation_service.py` | ban/mute/warn/unwarn/kick، سقف اخطار و هم‌گام‌سازی |
| `test_stats_service.py` | شمارنده پیام، جمع‌زدن آمار و پاک‌سازی |
| `test_resilience.py` | تلاش دوباره در خطای گذرای شبکه و عدم تلاش برای خطای منطقی |
| `test_help.py` | دکمه‌های بخش‌های راهنما و ساختار صفحه‌بندی |
| `test_panel_flow.py` | اجرای واقعی Dispatcher با ربات ساختگی: پنل، راهنما، دکمه‌ها، دستورها و قطعی شبکه |

تست‌های دیتابیسی روی SQLite درون‌حافظه اجرا می‌شوند و به `aiosqlite` و `pytest-asyncio` نیاز دارند.
`test_panel_flow.py` هیچ تماس شبکه‌ای با تلگرام ندارد (یک `BaseSession` ساختگی).

## ساختار

| پوشه | نقش |
| --- | --- |
| `core/` | تنظیمات، لاگ، نقش‌ها، مدت‌زمان، تاریخ شمسی، نرمال‌سازی متن، متن‌های فارسی |
| `domain/` | ساختارهای داده و تجزیه دستورها (`commands.py`) — مستقل از پلتفرم |
| `database/` | مدل‌ها، repositoryها و Migrationهای Alembic |
| `services/` | منطق برنامه (مدیریت کاربران، اخطار، آمار، شمارنده پیام، گزارش) |
| `platforms/base.py` | قرارداد مشترک پلتفرم‌ها |
| `platforms/telegram/` | همه کد وابسته به تلگرام: adapter، handlerها، middlewareها، پنل و کارهای پس‌زمینه |
| `platforms/telegram/jobs/` | حلقه پس‌زمینه: ذخیره آمار، گزارش ۲۳:۵۹، پاک‌سازی روزانه |
| `platforms/telegram/guards.py` | بررسی‌های مشترک: گروه، هویت مدیر، نقش و هدف دستور |

هر ماژول handler تابع `build_router()` دارد (نه روتر سراسری)، چون روتر aiogram فقط یک بار
به یک Dispatcher قابل اتصال است و این‌طوری ساخت دوباره Dispatcher در تست ممکن می‌شود.

## نکات

- جدول گروه‌ها `chat_groups` نام دارد، چون `groups` در MySQL 8 کلمه رزروشده است.
- تاریخ‌ها در دیتابیس UTC‌اند و به شمسی/وقت تهران نمایش داده می‌شوند. روز آمار و ساعت گزارش شبانه فعلاً برای همه گروه‌ها وقت تهران است.
- تلگرام اجازه نمی‌دهد ربات «همه پیام‌های یک کاربر» را پاک کند؛ این قابلیت (با ذخیره شناسه پیام‌ها) در فاز بعد می‌آید.
- متغیر `TELEGRAM_PROXY` برای پروکسی HTTP است. برای SOCKS باید `aiohttp-socks` را هم نصب کنید.
- درخواست تأیید مسدودی دائمی در حافظه نگه داشته می‌شود؛ اگر ربات ری‌استارت شود، درخواست‌های تأییدنشده منقضی می‌شوند (۲ دقیقه اعتبار).
- خطاهای گذرای شبکه (`ServerDisconnectedError`، `TimeoutError`، محدودیت نرخ تلگرام) خودکار تا ۳ بار با تأخیر فزاینده تکرار می‌شوند؛ اگر باز هم شکست بخورند، به کاربر پیام «ارتباط با سرور تلگرام برقرار نشد» نشان داده می‌شود و ربات متوقف نمی‌شود.
- ربات را با همان مفسر پایتونی اجرا کنید که وابستگی‌ها در آن نصب شده‌اند (`.venv`). اگر خطای `ModuleNotFoundError` گرفتید، venv فعال نشده است.
